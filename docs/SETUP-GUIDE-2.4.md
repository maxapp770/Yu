# دليل إعداد الهيثم 2.4

الإدارة والعميل والموصّل والريلز — 2026-09-13.


## ابدأ هنا — الخدمة المستقلة 2.4 والتوصيل والريلز

هذا المسار لا يحتاج تثبيت إضافة أو إنشاء DocType مخصص على ERPNext. يدير الخادم المستقل المحتوى والحسابات والجلسات والنشر، ويستخدم واجهات Frappe القياسية لقراءة بيانات النظام وإنشاء مسودات الطلبات.


1. افتح التطبيق الإداري ← الإعدادات العامة ← خدمة الربط.
2. ادخل بحسابك الإداري المنفصل، وليس حساب تكامل العملاء.
3. اختبر حساب التكامل ثم اختر الشركة والأسعار والمخزن.
4. فعّل الميزات التي تحتاجها فقط، ثم انشر محتوى الرئيسية.
5. أنشئ حساب عميل شخصياً مرتبطاً بسجل Customer موجود.


## مساحة ChatGPT المؤقتة

نسخة Sites تجربة ويب خاصة. الدخول إلى ChatGPT يحمي مساحة التجربة، ثم يتطلب التطبيق الإداري حساب ERPNext صاحب الصلاحية. لا يصل أندرويد مباشرة إلى الموقع الخاص لأن دخوله محمي بحساب ChatGPT.


1. افتح واجهة الإدارة أو واجهة العميل من صفحة التجربة.
2. في التجربة: قاعدة البيانات الدائمة D1 والصور R2، مع تشفير مفاتيح ERP والجلسات.
3. موعد الحملة يُطبّق عند أول طلب للخدمة بعد الموعد، وليس عبر عامل دائم.
4. مفاتيح العملاء معدّة على الخادم، واختيار الشركة والأسعار وتفعيل الطلبات يبقى لك.
5. للخدمة النهائية استخدم نطاق HTTPS ثابتاً ثم ابنِ تطبيقات أندرويد بعنوانه.


## الريلز — الإعداد والنشر 2.4

نافذة فيديو عمودية للأصناف والمجموعات، مع اختصار أحمر يتمدد من يسار الرئيسية. صور الدليل مأخوذة من اختبار فعلي للواجهة باستخدام بيانات وفيديو اختبار، وليست إثبات اتصال بمحتوى ERPNext الحقيقي.


1. الإدارة ← الرئيسية أو تسوق ← الريلز ومصادر الفيديو.
2. أضف رابطاً مباشراً أو ارفع فيديو أو افتح جلب وصف الصنف ومرفقاته.
3. اختر الأصناف بالبحث أو قارئ الباركود، واكتب أسماء المجموعات المطابقة.
4. حدّد الغلاف والعنوان والترتيب وبداية ونهاية الظهور.
5. احفظ المسودة ثم افتح النشر والجدولة وانشر المتجر. الحفظ وحده لا يظهر الفيديو للعملاء.
6. الإعدادات والحلقات في تبويب مستقل. يمكن إيقاف الريلز أو الاختصار أو الحلقات كل على حدة.


## مصادر الفيديو في ERPNext — دون إضافة

تستخدم الخدمة واجهات Frappe القياسية فقط. الجلب الإداري بحساب System Manager الشخصي، والجلب التلقائي العام بصلاحيات حساب تكامل العملاء.


1. لا يلزم إنشاء DocType أو حقل مخصص.
2. تأكد من قراءة Item وFile لحساب التكامل ضمن أذوناتك المطلوبة.
3. لا تغيّر المرفق الأصلي من خاص إلى عام لمجرد تشغيل الميزة؛ الاستيراد ينشئ نسخة مستقلة عند موافقتك.


| الحقل | وظيفته |
|---|---|
| Item.name | كود الصنف؛ اختيار الصنف بالبحث يربط الفيديو بمعرّف ثابت في التطبيق. |
| Item.description | تُقرأ روابط HTTPS من النص وعناصر a وvideo وsource دون تنفيذ HTML أو JavaScript. |
| Item.item_group | اسم مجموعة الأصناف الذي يربط حلقات الفيديو بالمجموعة. |
| File.attached_to_doctype | يجب أن تكون Item. |
| File.attached_to_name | كود الصنف نفسه، مع فلتر يمنع جلب مرفقات مستندات أخرى. |
| File.file_url | مسار ملف MP4 أو WebM أو رابط عام مباشر. |
| File.is_private | الملف الخاص لا يصل للعملاء تلقائياً. يحتاج موافقة المدير على استيراد نسخة للنشر، ثم الحفظ والنشر. |

| الحقل | وظيفته |

| shortcut / shortcutTitle | إظهار الاختصار أو إخفاؤه وتغيير نصه. |

| المشاهدة | بعد تشغيل جزء من الفيديو تُحفظ علامة مشاهد على الجهاز، وتصبح الحلقة رمادية. ليست عداد مشاهدات تسويقي على الخادم. |


## تشغيل الريلز وتوفير البيانات

مرّر عمودياً للتقليب، أو استخدم السهمين. يُوقَف الفيديو السابق ويُفصل مصدره عند الانتقال. يبدأ التشغيل مكتوماً ويمكن تشغيل الصوت. عرض الغلاف لا يحمّل الفيديو.


1. زر تسوق يفتح الصنف المرتبط، ومنها إضافة للسلة والمفضلة.
2. زر الإغلاق يعود إلى الصفحة التي كنت تتصفحها.
3. إيقاف التطبيق أو إخفاء الصفحة يوقف تشغيل الفيديو.
4. الرابط الخارجي يجب أن يبقى عاماً وصالحاً. ضع رابط الملف النهائي؛ النسخة الأصلية في أندرويد لا تتبع تحويلات الفيديو الخارجية.


| الحقل | وظيفته |
|---|---|
| dataSaver | مفعّل افتراضياً: يبدأ تحميل الفيديو فقط بعد النقر. يُحترم تفضيل توفير البيانات الذي يرسله المتصفح أيضاً. |
| autoPlay | يعمل تلقائياً مكتوماً للفيديو الظاهر فقط عند إيقاف توفير البيانات. |
| الترميز | الرفع MP4 أو WebM حتى 5 ميجابايت. يوصى بملف MP4/H.264 عمودي. يعتمد دعم الترميز الفعلي على الجهاز. |
| رابط خارجي | الرابط المباشر MP4/WebM يعمل داخل الريلز. رابط صفحة YouTube أو Facebook أو Instagram أو Vimeo يفتح في مصدره؛ لا نحوله إلى ملف فيديو ولا ننفذ iframe من وصف الصنف. |


## الاستضافة والنسخ الاحتياطي وتغيير التكامل

ملفات الريلز في تخزين الخدمة المستقلة، وبياناتها محفوظة على الخادم. لا توجد مفاتيح ERP داخل رابط الفيديو أو APK. نشر نسخة من مرفق خاص إجراء إداري صريح مسجل.


1. خدمة ERPNext الفعلية لم يؤكد هذا الإصدار الوصول إليها؛ اختبارات المصدر والصلاحيات جرت على نظام اختبار محاكى.
2. المعاينة المنشورة خاصة بحساب ChatGPT. اتصال أندرويد المباشر يبقى بانتظار عنوان HTTPS مستقل.


| الحقل | وظيفته |
|---|---|
| /v1/reels-media/ | يخدم الفيديو المنشور فقط ويدعم HTTP Range. الإخفاء أو انتهاء الفترة يمنع الوصول حتى لمن احتفظ بالرابط. |
| النسخ الاحتياطي | في الخدمة المستقلة انسخ قاعدة البيانات ومجلد media ومفتاح التشفير المحمي. في نسخة Sites توجد الملفات في R2 وبياناتها في D1؛ لا يكفي نسخ الواجهات. |
| تغيير ERP | جيل التكامل يمنع إظهار فيديوهات الاتصال السابق أو إعادة استخدام ملفه تلقائياً. أعد الجلب أو الرفع والربط ثم انشر للاتصال الجديد. |
| الروابط العامة الخارجية | يتصل جهاز العميل بمضيف الفيديو العام في معاينة الويب. لا تُرسل مفاتيح ERP إلى ذلك المضيف. |

1. حساب System Manager يفتح كل أقسام إدارة المتجر.
2. الأدوار المختارة للتقارير تفتح التقارير فقط.
3. إذا كان الحساب يتطلب تحققاً إضافياً لا يتم تعطيله؛ استخدم مفتاح API شخصياً مخولاً.

5. حساب admin / 123456 لمعاينة الواجهة المحلية فقط، وليس حساباً على الخدمة أو ERPNext.

## الأدلة والتلميحات

نافذة الأدلة مستقلة داخل لوحة الإدارة. يوجد بحث في كل الفصول، وتلميحات تعليمية قرب الحقول. بعض النصوص الطويلة داخل الصورة التسويقية نفسها تتغير برفع صورة جديدة، أما عناوين الأقسام وشارات العرض فتتغير من الحقول.


## إدارة الرئيسية والتسويق

كل أقسام الرئيسية القديمة موجودة في المسودة: النصوص والاختصارات والبانرات والصفقات والمجموعات والاقتراحات ووصل حديثاً والأكثر مبيعاً والتذييل. احفظ تغييراتك ثم انشرها لتظهر في واجهة العميل.


1. من الرئيسية افتح تخطيط الأقسام واضبط الترتيب والإظهار وعنوان القسم.
2. افتح تبويب النصوص لتعديل عبارات مثل «تسوق بأقل الأسعار».
3. في التصميم أضف صورة أو عدة صور وحدد الوجهة لكل واحدة.
4. استخدم فلتر السعر يساوي 500 لإنشاء حملة «أي قطعة 500».
5. الفلاتر تعمل على بيانات الكتالوج المحملة؛ الحركة التاريخية تحتاج مصدراً موصولاً ولا تُختلق.
6. راجع المسودة ثم انشر إصداراً من النشر والجدولة.

## النقل وتغيير مفاتيح التكامل

عند تغيير المفاتيح لنفس ERPNext تنتهي الجلسات وتُوقف الميزات لحين المراجعة، مع بقاء روابط العملاء. عند تغيير أصل ERPNext يزيد جيل التكامل وتُوقف روابط العملاء القديمة. لا تُرسل سلة قديمة بصمت إلى شركة جديدة.

2. سوّ كل طلب إرسال غير محسوم على الخادم القديم.
3. خذ نسخة احتياطية من قاعدة الخدمة والصور ومفتاح التشفير.
4. أضف نطاق ERP الجديد إلى قائمة السماح لدى مسؤول الاستضافة.
5. اختبر الاتصال من اللوحة ثم فعّله.
6. أعد اختيار الشركة والأسعار وربط العملاء بالسجلات الصحيحة.
7. اختبر بحساب عميل ثم أنهِ الصيانة.
8. إذا توقف ERP القديم تماماً قبل النقل، لن تتجاوز الخدمة التحقق من المدير. يحتاج مسؤول الاستضافة إجراء استعادة محكوماً ونسخة احتياطية؛ ليس هذا تغييراً برمجياً في تطبيق العميل.

3. في طلباتي ← التوصيل والمندوبون أنشئ حساب الموصّل واربطه بسجل Driver نشط.
4. اربط العميل بحساب المتجر؛ سيظهر له رمز الاستلام في تفاصيل الطلب.
5. اعتمد Sales Order وDelivery Note في ERPNext وفق سير العمل المعتاد، ثم أسند سند التسليم إلى الموصّل من دورة التوصيل.
6. راجِع أحداث التسليم والعهد من نفس اللوحة. لا تختبر بالكتابة على طلبات العملاء دون اختيارها عن قصد.


## حساب الموصّل — الدخول والتعطيل

الحساب شخصي داخل الخدمة ومربوط بسجل السائق والشركة. لا يحصل الموصّل على مفتاح تكامل ERPNext ولا دور مدير.


1. أرسل بيانات الدخول إلى الموصّل عبر وسيلة التواصل التي تعتمدها؛ التطبيق لا يرسل كلمة المرور تلقائياً.
2. الدخول من حسابي ← الاتصال بحساب الموصّل، أو مدخل الموصّل في صفحة التجربة.
3. عند فقدان كلمة المرور، يعيد المدير تعيينها من الحساب. لا توجد استعادة بريدية غير مهيأة.


| الحقل | وظيفته |
|---|---|
| user | بريد دخول الموصّل. يمنع تكراره داخل جيل التكامل. |
| driver | اسم سجل Driver فعلي ونشط في ERPNext. |
| enabled | إيقاف الحساب يمنع الطلب التالي من الجلسات القائمة. |
| password | 12 محرفاً على الأقل؛ تحفظ كبصمة. إعادة تعيينها تنهي صلاحية الجلسات السابقة. |
| online | يغيّرها الموصّل لتفعيل أو إيقاف قبول المهام. |


## إسناد الشحنة — Sales Order وDelivery Note

المهمة مرتبطة بسند تسليم واحد معتمد. يمكن أن يحتوي طلب البيع على عدة سندات، لكل منها مهمة مستقلة، وتظهر جميعها في تتبع العميل.


| الحقل | وظيفته |
|---|---|
| sales_order | Sales Order معتمد docstatus=1 ومن الشركة المحددة، وليس مغلقاً. |
| delivery_note | Delivery Note معتمد، غير مرتجع، يطابق العميل والشركة. جميع items.against_sales_order تتبع الطلب المختار. |
| items / packed_items | تُقرأ الأصناف والمكونات والكميات من سند التسليم. |
| expected_cash | المبلغ المتبقي الذي راجعه المدير؛ لا يُحسب آلياً من إجمالي السند لأن الطلب قد يكون مدفوعاً جزئياً. |
| commission | مستحق تشغيل لهذه المهمة، لا يمثل قيد صرف. |
| delivery | اسم المستلم وهاتفه والعنوان وملاحظة الوصول. |


## رحلة الموصّل وإثبات التسليم

المهام وحالاتها محفوظة في الخدمة. الموصّل لا يرى مهام موصّل آخر، ولا ينشئ أو يعتمد مستندات ERPNext من حسابه.


1. طلب جديد ← قبول ← استلام الشحنة من المتجر ← في الطريق ← تسليم.
2. لا يمكن القفز مباشرة إلى التسليم.
3. عند التسليم أدخل رمز العميل واسم المستلم وأكد النقد المطابق للمبلغ المطلوب.
4. الرمز لا يظهر للموصّل في أي استجابة. محاولات الرمز محدودة على الخادم.
5. إذا انقطع الاتصال، حدّث المهمة للتحقق من الحفظ. معرّف العملية ورقم مراجعة المهمة يمنعان تكرار التسليم والتحصيل.
6. البيانات الحساسة لا تحفظ في localStorage. عند تعذر الاتصال لا تدعي الشاشة أن الإجراء حُفظ.


## تتبع العميل وإشعارات التوصيل

تظهر الشحنات ضمن تفاصيل طلب البيع الخاص بالعميل، مع حالة كل شحنة وتوقيتها ورمز استلامها.


1. افتح حساب المتجر ثم طلباتي واختر طلب البيع.
2. أعطِ رمز الشحنة للموصّل عند استلامها فقط.
3. إشعارات مراحل التوصيل تصل إلى مركز الإشعارات داخل التطبيق عند التحديث.
4. هذه إشعارات داخل التطبيق، وليست Push في خلفية هاتف مغلق؛ Push يحتاج مزوداً وإعداداً منفصلاً.


## التعذر والاعتذار والإعادة

يُسجّل السبب مع وقت الإجراء. يمكن إعادة الإسناد قبل استلام الشحنة فقط. بعد الاستلام تبقى الشحنة في عهدة الموصّل حتى يؤكد المدير عودتها.


1. اعتذار عن مهمة جديدة: اكتب سبباً واضحاً ثم يمكن للمدير إسنادها لموصّل آخر.
2. تعذر بعد الاستلام: يسجّل الموصّل السبب؛ يؤكد المدير استلام الشحنة المعادة فعلياً.
3. زر إغلاق المهمة لا ينشئ مرتجع مخزون أو إشعاراً دائناً. أكمل مستند المرتجع الصحيح في ERPNext عند الحاجة.
4. المهمة المعادة مغلقة. تستخدم شحنة جديدة بسند تسليم جديد لإعادة الإرسال.


## العهد النقدية — Payment Entry

تأكيد التسليم يسجل النقد كعهدة لدى الموصّل. إغلاق العهدة يتطلب استلام المدير الفعلي للنقد وربط سند قبض معتمد؛ لا ينشئ التطبيق قيداً تلقائياً اعتماداً على زر الموصّل.


1. من دورة التوصيل افتح المهمة المسلّمة ثم استلام العهدة.
2. اختر سند القبض بعد تسجيله واعتماده وفق حسابات شركتك.
3. يُستخدم سند القبض لتسوية مهمة واحدة لمنع تكرار استخدام المبلغ.
4. تظهر مستحقات الموصّل منفصلة، ولا تعد صرفاً محاسبياً.


| الحقل | وظيفته |
|---|---|
| docstatus | يجب أن يساوي 1 في Payment Entry. |
| payment_type / party_type | Receive / Customer. |
| party / company | نفس عميل طلب البيع وشركته. |
| paid_to_account_currency | مطابقة لعملة المهمة. |
| references | يحتوي Sales Order المحدد مع allocated_amount يغطي النقد المحصل. |
| cash_received | تأكيد المدير أنه استلم النقد بالفعل. |


## إرفاق إثبات الرحلة في ERPNext وتغيير الربط

زر إرفاق الإثبات يضيف Comment إلى Delivery Note بحساب المدير، يتضمن مرجع المهمة وحالتها والتحصيل. سند التسليم المعتمد هو مرجع المخزون؛ تعليق الإثبات لا يغيّر docstatus أو ينشئ قيوداً.


1. يتحقق الخادم من System Manager ثم يستخدم صلاحيات المستخدم نفسه في ERPNext.
2. عند ضياع الرد تحفظ الحالة unknown. زر المراجعة يبحث عن العلامة نفسها، ولا يعيد الكتابة بشكل أعمى.
3. لا يكتمل نقل التكامل أو تغيير الشركة والأسعار والمخزن قبل إغلاق المهام وتسوية العهد ومراجعة النتائج المعلقة.
4. تغيير عنوان ERPNext ينشئ جيل تكامل جديد؛ لا تُنقل حسابات الموصّلين والمهام القديمة إلى شركة أو خادم آخر تلقائياً.
5. احتفظ بنسخة قاعدة الخدمة ومفتاح التشفير عند نقل استضافتها. الصور والنسخ الاحتياطية منفصلة عن مفاتيح الدخول.
