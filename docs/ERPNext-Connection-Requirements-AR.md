# متطلبات ربط الهيثم بـ ERPNext / Frappe — الإصدار 1.9

أرسل المعلومات غير السرية التالية أولاً. لا نحتاج كلمة مرور Administrator، ولا يوضع API Secret في APK أو JavaScript أو إعدادات العميل.

| المطلوب | التفاصيل |
|---|---|
| رابط الموقع | عنوان HTTPS الكامل، وهل يوجد موقع اختبار منفصل |
| الإصدار | إصدار ERPNext وإصدار Frappe والتطبيقات الإضافية ذات الصلة |
| الاستضافة | Frappe Cloud أو خادم خاص؛ هل يمكن تثبيت تطبيق Frappe مخصص وتشغيل المجدول والعمال؟ |
| حساب الربط | اسم مستخدم خدمة مستقل، والأدوار الممنوحة له. احتفظ بحسابك الإداري منفصلاً |
| الشركة والأسعار | Company، العملة، Selling Price List، الضريبة، وهل السعر يشملها، وأسعار العملاء الخاصة |
| المخزون | المستودعات المسموح البيع منها، ومعنى المتاح: الفعلي أم المتاح بعد الحجز |
| الأصناف | 3–5 أكواد اختبار مع صور وباركود ووحدة؛ وصنف عرض أب غير مخزني مع Product Bundle ومكوناته |
| الحركة | اسم تقرير الحركة المستخدم، وهل المصدر Sales Invoice أم Sales Order أم Stock Ledger، وطريقة معالجة المرتجعات والفترة |
| العميل | الربط بين User وCustomer، وطريقة تسجيل الدخول الحالية، ومثال عميل اختبار |
| الولاء والعمولة | اسم Loyalty Program، شروطه، واسم DocType/الحقول المستخدمة للتسويق بالعمولة إن كان مخصصاً |
| دورة الطلب | هل يبدأ Sales Order كمسودة؟ من يؤكده؟ المستند المستخدم للتوصيل والتحصيل والإرجاع |
| الإشعارات | مزود Push المتاح إن وجد، ومصدر موافقة المشتركين، وإعداد البريد للنشرات |

## الصلاحيات المقترحة

نبدأ بقراءة الكتالوج والأسعار والحزم والبيانات المجمعة اللازمة للتسويق ضمن الشركة والمستودعات المحددة. لا يحتاج مستخدم الربط العام دور System Manager ولا صلاحية شاملة على بيانات العملاء أو الفواتير.

أثناء تنفيذ الربط نحدد خدمات مخصصة محدودة للطلبات والتوصيل والتقييمات والإعدادات. تتحقق الخدمة من هوية العميل وملكية الطلب أو إسناده للموصل في كل طلب، وتقرأ دور System Manager من جلسة مدير النظام عند تعديل الإدارة. وجود زر الإدارة في تطبيق العميل لا يكفي لحماية البيانات؛ الخادم هو الذي يرفض العمليات غير المصرح بها.

تدعم Frappe المصادقة عبر رموز API وغيرها، وتعمل صلاحيات الرمز بهوية مستخدمه. التصميم المقترح يحتفظ بسر مستخدم الخدمة في الخادم، ويعطي كل عميل جلسة خاصة به. تُجهز بيانات الاعتماد عبر إعداد آمن للخادم عند بدء الربط، دون إرسال كلمة مرور الحساب الإداري هنا. [مرجع REST API الرسمي](https://docs.frappe.io/framework/user/en/api/rest).

## الأتمتة ومصدر البيانات

سنطابق تعريف الحركة مع تقريرك قبل اعتماد الترتيب. يتيح ERPNext تحليل الأصناف والكميات خلال فترة، لكن النتائج تتغير باختلاف المستند وحالته والتواريخ والمرتجعات. [تقارير المبيعات الرسمية](https://docs.frappe.io/erpnext/sales-analytics).

يُنفذ النشر المستمر على مجدول Frappe، مع سجل تشغيل ومنع تكرار وإعادة محاولة؛ لا يعتمد على بقاء هاتف العميل مفتوحاً. إرسال Push والبريد يحتاج ربط قنوات الإرسال أيضاً. [مجدول المهام الرسمي](https://docs.frappe.io/framework/user/en/api/background_jobs).

تفعيل واجهة الولاء لا ينشئ رصيداً. يُعتمد الاكتساب والاستبدال حسب البرنامج والمبيعات المعتمدة، وتظل إعدادات الظهور والإتاحة في التطبيق منفصلة عن القيود المالية. [برنامج الولاء الرسمي](https://docs.frappe.io/erpnext/loyalty-program).

## الخطوة التالية بعد وصول المعلومات

فحص قراءة محدود على بيئة الاختبار، مطابقة كتالوج وأسعار وحزم، توثيق الجلسات والأدوار، ثم تجربة طلب واحد من العميل حتى التوصيل والإرجاع. بعدها نفعّل مصدر الحركة والمجدول وقنوات الإرسال. لا تنشئ نسخة 1.9 الحالية مستندات في ERPNext ولا ترسل إشعارات خارج الجهاز.
