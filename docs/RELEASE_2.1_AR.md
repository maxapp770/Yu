# إصدار 2.1.0 — 12 سبتمبر 2026

هذه نسخة مراجعة تتضمن تطوير الاتصال والنشر وحسابات العملاء والتوثيق. لم يكتمل الاختبار الحي الشامل أو اعتماد إصدار Google Play.

## ما تغير

- التطبيقان منفصلان بمعرفَي حزمة مختلفين. لا يحتوي APK العميل على ملفات الإدارة أو حساب المراجعة.
- رابط الإدارة قابل للإدخال، واختبار REST بالمفاتيح يقرأ الهوية والشركات وقوائم الأسعار والمخازن. حساب المدير يبقى منفصلاً عن حساب التكامل.
- عنوان خدمة العميل يحدد عند البناء باستخدام HEC_SERVICE_ORIGIN. لا توضع مفاتيح ERPNext أو كلمة مرور مشتركة في تطبيق العملاء.
- حفظ المحتوى ينشئ مسودة؛ النشر والجدولة والاستعادة تستخدم إصدارات ثابتة على الخادم. إعداد الربط وروابط العملاء تنفذ عند الحفظ.
- العميل يجلب المحتوى عند الفتح والعودة، ويفحص نسخة المحتوى كل 60 ثانية أثناء الاستخدام دون مقاطعة حقل نشط، ويعيد تحديث بيانات الكتالوج دورياً.
- وضع الصيانة يقفل استقبال الطلبات الجديدة ويسلسل العملية مع الطلبات الجارية قبل النقل. هوية المتجر store_id تكشف نقل قاعدة بيانات غير مطابقة.
- إنشاء Website User وربطه إلى Customer وCompany من الإدارة، مع كلمة مرور خاصة ورفض الكتابة فوق مستخدم موجود. لا ترسل رسائل بريد تلقائياً.
- تغيير كلمة مرور العميل عبر Frappe مع إنهاء الجلسات الأخرى وفق دورة النظام. كلمات المرور والمفاتيح لا تحفظ في التطبيق.
- تفاصيل الطلب تتضمن items وpacked_items. إشعار الطلب الخاص يفتح تفاصيله بعد فحص ملكيته، والقراءة مقيدة بمستلمه.
- تلميحات قابلة للنقر لحقول الإدارة، وشرح أزرار الصفحة، ودليل بحث تفاعلي داخل الإدارة وملف HTML مستقل.
- جرد مصوّر لكل DocType مضاف وحقوله، مع فحص metadata مباشر من الخادم بعد تركيب الخدمة.

## التحقق الفعلي من الخادم

نجحت مصادقة REST للحساب support@wahatalhaitham.com وقراءة شركتين وقائمتي أسعار وستة مخازن متاحة له. لم تنفذ كتابة على نظامكم.
أعاد Frappe HTTP 417 ورسالة أن تطبيق hec_bridge غير مثبت. ظهر 403 / Cloudflare 1010 في فحوص سابقة؛ لا يصح اعتباره العائق الوحيد بعد نجاح REST.
لم تثبت صلاحية System Manager لحساب التكامل؛ الحساب الإداري المخوّل لا يزال مطلوباً للرحلة الحية.
تقرير القراءة الفعلية المرفق لا يحتوي المفتاح أو السر. اختبارات الواجهات تستخدم بيانات وعقد API محلياً، وليست مستندات فعلية من ERPNext.

## الاختبارات وحدودها

- 29 اختبار تراجع لعقد خدمة 2.0.
- 19 اختباراً إضافياً لوظائف النشر والصيانة والصلاحيات وهوية المتجر والحساب والملفات المسموحة داخل Android.
- 21 رحلة متصفح تشمل الفصل، المسودة والنشر، العميل والطلب والإشعار وكلمة المرور وحماية النقل، على عروض 320 و390 و460 بكسل.
- بناء APK لكل دور باستخدام SDK 35 وفحص التوقيع والمحتويات.
- الدليل فُحص على شاشة هاتف؛ الصور التعليمية مولدة من جداول الكود، وصور التطبيق من الاختبار المحلي. تقرير REST وحده بيانات فعلية من الخادم.
- لم يُشغّل التطبيق على هاتف أو محاكي Android في هذه البيئة. لا يُعتبر فحص المتصفح إثباتاً للكاميرا والمشاركة الأصلية أو Android Keystore.

## متطلبات لم تكتمل بعد

- تركيب hec_bridge على موقعكم، تنفيذ migrate، تشغيل Scheduler وworkers، واختبار نسختكم وتخصيصاتكم الفعلية.
- تجربة حساب مدير System Manager وحساب عميل فعلي، والنشر ثم إنشاء Sales Order وفحص packed_items ومنع التكرار على قاعدة البيانات الحقيقية.
- Push يحتاج إعداد مشروع ومزود إرسال. لا توجد وعود بوصول فوري لكل جهاز.
- الدورات المالية للولاء والعمولات والمحفظة، وحركات التوصيل والمرتجعات والأتمتة التسويقية المبنية على حركات ERP تحتاج محولات مطابقة لنظامكم. تبقى مفاتيح الربط غير المدعومة مغلقة؛ المحاكاة القديمة لا تمثل تنفيذ تلك الدورات على الخادم.
- نمط خدمة HEC المستضافة داخل Frappe هو المدعوم. ربط Gateway مستقلة بخادم ERP آخر ومفاتيح محفوظة على Gateway يحتاج محولاً إضافياً؛ تغيير عنوان الإدارة وحده لا ينقل العملاء.
- النسخ موقعة بمفتاح المراجعة لاستمرار التحديثات، وليست حزم Google Play إنتاجية معتمدة.

## ملفات المتطلبات

- docs/HEC-Live-Setup-Guide-2.1-AR.html: دليل مستقل يعمل دون اتصال، يحتوي صوراً وبحثاً وقائمة تحقق محلية وطباعة.
- docs/DOCTYPE_SPECS.json: الجداول الخاصة وحقولها بالضبط.
- integration/frappe/hec_bridge: مصدر الإضافة القابل للتركيب.
- tools/live_journey.py: فحص حي للقراءة افتراضياً؛ --place-order ينشئ طلباً اختبارياً حقيقياً واحداً ويعيد نفس المعرف للتحقق من عدم التكرار.

## نقل النظام

1. احتفظ بنفس عنوان HTTPS الذي بُني عليه تطبيق العملاء.
2. شغّل الصيانة، وانتظر اكتمال الطلبات السابقة، ثم انسخ قاعدة البيانات والملفات وencryption_key مع حماية الأسرار.
3. استعد الموقع والإضافة في الخادم الجديد مع store_id وروابط العملاء وسجلات HEC Order Request نفسها.
4. أوقف مهام الجدولة على الخادم القديم عند تفعيلها في الجديد، وحوّل النطاق بعد تجهيز TLS.
5. افحص الهوية والصلاحيات والشركة والقائمة والمخزن ثم اختبر الطلبات قبل إنهاء الصيانة.
6. لا ترجع لنسخة احتياطية قديمة بعد استقبال معاملات جديدة دون تسويتها أولاً.

تدوير مفتاح المدير يحتاج إعادة دخوله فقط. تغيير integration_user يراجع صلاحيات المستخدم الجديد على الخادم؛ لا يحتاج تحديث APK العميل.
