# بنية الأداء والتخزين — HEC 2.6.0

## القرار المعماري

التطبيق Android أصلي يحتوي واجهة WebView محلية. لذلك تُبنى الواجهة على جهاز العميل (CSR عملياً) من ملفات داخل APK، بينما تبقى بيانات ERPNext ومفاتيح التكامل خلف الخدمة المستقلة. هذا مناسب للهواتف والإنترنت الضعيف في اليمن، ولا يحوّل التطبيق إلى موقع يعتمد على تحميل حزمة كبيرة عند كل فتح.

## ما تم تفعيله

- `performance.js` يُحمّل مبكراً ويطبق `decoding=async` و`loading=lazy` و`fetchpriority=low` للصور التي تُنشأ ديناميكياً، ويجعل الفيديو `preload=none`.
- إيقاف التشغيل التلقائي للفيديو عند `Save-Data` أو تفضيل تقليل الحركة.
- شريط حالة اتصال غير حاجب للواجهة؛ عند الانقطاع تظهر رسالة مختصرة ولا تُدّعى عملية حفظ غير مؤكدة.
- ذاكرة مؤقتة محدودة المدة عبر `HECPerf.cache` للاستخدام في الوحدات الجديدة، مع تجاهل آمن لفشل الحصة أو الوضع الخاص.
- كتالوج ERPNext محفوظ محلياً في `hec.erp.catalog.v1` ويُستخدم للمشاهدة عند تعذر الاتصال، ثم يُحدّث عند عودة الشبكة مع إظهار حالة البيانات القديمة.
- الصور المرفوعة تحفظ في IndexedDB، والطلبات المحلية لا تُرسل إلا بعد تأكيد الخدمة.

## Code Splitting

الملفات مقسّمة وظيفياً إلى وحدات (كتالوج، تجارة، ريلز، إدارة، توصيل)، لكن الإصدار الحالي يحافظ على تحميلها بالترتيب عبر `defer` لضمان توافق WebView القديمة. لا نستخدم `import()` أو bundler يغير ترتيب الاعتماديات؛ إدخال ذلك عشوائياً قد يعطل أجهزة Android القديمة. المرحلة التالية الموصى بها هي إنشاء حزم `customer-core` و`admin-tools` أثناء البناء مع اختبار كامل لكل دور.

## لماذا لا يوجد Service Worker؟

التطبيق يُشغّل من أصول Android محلية، وService Worker ليس حدود التخزين الموثوقة لهذا النوع من WebView. البديل الصحيح هو cache الخدمة المستقلة + IndexedDB للصور + كتالوج محلي محدود. إذا أُنشئت نسخة ويب PWA لاحقاً، يضاف Service Worker منفصل للنسخة المنشورة فقط.

## فحص الأداء قبل الإصدار

1. شغّل اختبارات JavaScript وPython الموجودة في `tests/`.
2. اختبر أول فتح مع اتصال ضعيف، ثم افتح التطبيق دون اتصال وتحقق من ظهور آخر كتالوج محفوظ.
3. تحقق من عدم تحميل الفيديو قبل ظهوره ومن عدم وجود مفاتيح ERPNext داخل APK.
4. اختبر Android WebView قديم وحديث، مع تفعيل `Save-Data` وتقليل الحركة.
5. لا تُفعّل ضغطاً أو bundling خارجياً دون الاحتفاظ بنسخة source map واختبار مسارات الإدارة والباركود والريلز.

## حدود مؤكدة

التخزين المحلي ليس مصدراً محاسبياً. السعر والمخزون والطلب النهائي يجب أن يؤكده ERPNext عبر الخدمة. تغيير رابط ERPNext يتم من إعدادات الخدمة، ولا تُضمّن مفاتيح API أو كلمة مرور المدير في تطبيق العميل.
