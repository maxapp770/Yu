# خطة المرحلة الثانية — الربط مع ERPNext

هذه خطة تنفيذ، وليست تكاملاً منفذاً أو توثيقاً معتمداً لإصدار محدد. يجب أولاً فحص إصدار ERPNext/Frappe وإعدادات الموقع والصلاحيات قبل تثبيت أسماء الموارد والعقود.

## نقطة البدء في الكود

الكتالوج المحلي في `data.js`. في المرحلة التالية تُستبدل طريقة تحميل البيانات بمستودع فعلي يعيد نموذج المنتج نفسه بعد تحقق وتحويل صريحين. `repository.submitOrder` يرفض الإرسال عمداً حالياً. لا توجد عناوين خوادم أو مفاتيح أو اتصالات مخفية.

## ترتيب العمل المقترح

1. توفير بيئة اختبار ونسخة API المعتمدة وحساب محدود الصلاحيات، وفحص حقول المنتجات والوحدات والأسعار والعملاء.
2. تعريف نموذج موحد للمنتج يتضمن المعرف والاسم والصورة والوحدات والأسعار والمخزون.
3. تنفيذ تسجيل الدخول وإدارة الجلسة وانتهائها واسترجاع الحساب. لا تستخدم كلمة مرور وهمية أو مفتاح مسؤول مشترك داخل التطبيق.
4. استبدال البيانات المحلية بنتائج API مع حالات تحميل وفشل وإعادة محاولة واضحة.
5. جعل حساب الأسعار والتخفيضات والضرائب والشحن والمخزون معتمداً على الخادم، وليس قيم الواجهة المحلية.
6. إرسال الطلب مع مفتاح منع تكرار، ثم عرض رقم وحالة الطلب اللذين يؤكدهما الخادم. المسودة الحالية لا تتحول إلى طلب مرسل دون تأكيد.
7. مزامنة المفضلة والعناوين عند تسجيل الدخول وفق قرار واضح بشأن دمج بيانات الضيف.
8. وضع الإدارة الحقيقية خلف تحقق صلاحيات على الخادم. أزيلت معاينة الإدارة المحلية في 1.3؛ اللوحة الجديدة محجوبة حتى يعود دور System Manager من جلسة الخادم. راجع MANAGEMENT_AR.md وعقد النقل management-api.js.
9. اختبار رفض الوصول وتغيير الأسعار ونفاد المخزون وانقطاع الشبكة وتكرار الإرسال وانتهاء الجلسة.
10. تفعيل الأذونات والاتصالات اللازمة فقط بعد مراجعة السياسة، وتوقيع إصدار إنتاجي بمفتاح يملكه صاحب التطبيق.

## معلومات مطلوبة عند بدء الربط

عنوان بيئة الاختبار، الإصدار، مخطط المنتجات والأسعار والوحدات، المستودع والشركة والعملات، آلية دخول العملاء، سياسة الضريبة والشحن، والرحلة المطلوبة لتحويل الطلب إلى مستندات ERPNext. تُمرر الأسرار عبر وسيلة إعداد آمنة خارج المصدر؛ لا تُلصق داخل JavaScript أو APK.

## المندوب وخيارات المنتج في تحديث 1.1

`courier.js` يدير معاينة محلية منفصلة، ولا يمثل نموذج صلاحيات أو محاسبة إنتاجياً. يجب اعتماد انتقالات القبول والرفض والتسليم والتحصيل على الخادم، مع منع تكرار العملية وربط المندوب بالطلبات المسموح له بها. الإحصائيات والعمولات والفترات الزمنية تحتاج سجلاً مالياً معتمداً. خيارات المنتج معرّفة بمعرف مستقل في السلة؛ يجب ربطها بمعرف الخيار الصحيح وسعره ومخزونه، مع إعادة تسعير المسودة عند إرسالها.
