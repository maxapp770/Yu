# ربط ERPNext لاحقاً — عقد 1.4

لم يحدث اتصال بنظام ERPNext في هذا الإصدار. لا مفاتيح أو أسماء نطاقات ERP مخمنة. تطبيق المراجعة يعمل بكتالوج وصلاحيات محلية. يجب التحقق من الإصدار الفعلي وحقول الموقع قبل اعتماد أي مطابقة.

| الوظيفة | نقطة الربط المجهزة | متطلبات الخادم |
|---|---|---|
| الإدارة | `HECManagementTransport.session/list/save/archive/logout` | هوية موثقة غير Guest، System Manager، صلاحية المستند وسير العمل |
| محتوى المتجر | `HEC.repository.getExperienceConfig()` | إعداد عام منشور للقراءة، منفصل عن حق التعديل |
| المنتجات | كود ثابت وخيارات ووحدة وسعر | كتالوج وأسعار ومخزون معتمد، لا ثقة بسعر العميل |
| Product Bundle | `HECOfferEngine.fromERP`، new_item_code وitems/item_code/qty | تأكيد مخطط الموقع، سعر الأب والمكونات من قائمة الأسعار |
| Promotional Scheme | تعريف مخطط فقط، مع requiresServerEvaluation | تقييم الشروط والخصومات والسلع المجانية على الخادم |
| توزيع إجمالي الحزمة | مبلغ الوحدة/حصة الصف بالنسبة/باقي تلقائي | اعتماد الإجمالي والتقريب والضريبة والعملات في الخادم |
| مشاركة السلة | أكواد الأصناف والخيارات والكميات | حل الأكواد وإعادة التسعير وتحقق الصلاحيات عند الشراء |
| الطلبات والتحصيل | مسودات محلية حالياً | معرف منع تكرار الطلب، انتقالات حالة معتمدة وتدقيق |

لا يُنشر `management-preview.js` أو حساب admin/123456 في بناء الإنتاج. لا يقبل الخادم reviewOnly، ولا تُرسل كلمة سر المراجعة إلى النظام الخارجي. القالب `integration/erpnext/management_guard.py` يوضح حارس الدور والمستندات ولا يُعد تكاملاً منشوراً.

خطوات المرحلة التالية: تثبيت مخطط ERP الفعلي وأدواره، إعداد خدمة HTTPS وصلاحياتها، استبدال الناقل المحلي، ربط نشر إعداد المحتوى لجميع الأجهزة، ربط Product Bundle ومخططات الترويج، ثم اختبارات مستخدمين وصلاحيات وسحب الدور والتعارض وفقد الشبكة. روابط السلة الحالية لا تزامن تعديلات الكتالوج المحلية الخاصة بين الأجهزة.

المراجع: [REST API](https://docs.frappe.io/framework/user/en/api/rest)، [المستخدمون والصلاحيات](https://docs.frappe.io/framework/user/en/basics/users-and-permissions). مطابقة حقول العروض الحالية مبدئية إلى حين التحقق من النظام الخارجي الفعلي.
