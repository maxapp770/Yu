# لوحة تحكم HEC — المرحلة الأولى 1.3

أُضيفت لوحة تحكم مستقلة ومتجاوبة تحافظ على هوية الهيثم. الوصول إليها مقصور على دور `System Manager` الذي تعيده جلسة موثّقة من ERPNext. اتصال ERPNext مؤجل بحسب الطلب؛ لذلك **اللوحة محجوبة في APK الحالي ولا يوجد زر معاينة أو حساب مسؤول محلي لفتحها**. الصور المرفقة للوحة أُنتجت باختبار منفصل يحاكي استجابة الخادم؛ ليست حساباً أو بيانات متجر حقيقية.

## الأقسام المنفذة

| القسم | الواجهة المتاحة بعد التحقق من الصلاحية |
|---|---|
| المنتجات والمخزون | بحث، عرض، إضافة، تعديل، أرشفة، السعر والوحدة والعلامة والوصف والخيارات والصورة؛ المخزون للقراءة |
| الأقسام والتصنيفات | القسم الأب والصورة والترتيب والإظهار |
| ترتيب الرئيسية | نوع القسم وترتيبه وبنره وإظهاره |
| الحملات والعروض | المنتجات والصور وفترة العرض والإظهار |
| الساعة الذهبية | المنتجات والبنر ووقت البدء والانتهاء |
| الطلبات | مراجعة الحالة والملاحظات؛ القيم المالية للقراءة |
| المرتجعات | مراجعة الطلبات وأسبابها وحالتها |
| المحفظة وطلبات الرصيد | مراجعة الطلبات؛ لا يوجد تعديل مباشر للأرصدة |
| نقاط الولاء | قواعد الاكتساب والاستبدال والصلاحية |
| التسويق بالعمولة | طلبات الاشتراك ونسبة العمولة والحالة |
| الرسائل والدعم | الرسالة والعميل والرد المقترح والمتابعة |
| الإشعارات | المحتوى والجمهور وموعد النشر |
| العملاء والعناوين | عرض البيانات المعتمدة من النظام |
| التوصيل والمندوبون | إسناد التوصيل ومتابعة الحالة |
| المستخدمون والصلاحيات | قراءة الأدوار المعتمدة من ERPNext؛ دون منح محلي |
| إعدادات المتجر والتواصل | بيانات المتجر وروابطه وسياساته |
| الكوبونات | الخصم والحد الأدنى وحد الاستخدام والصلاحية |
| السلال المهملة | عرض سجلات السلال المسجلة من النظام |
| النشرات البريدية | إعداد المحتوى وجدولته للمشتركين الموافقين |
| الفيديوهات | عنوان الفيديو ورابط YouTube والقسم والترتيب |
| التقارير | ملخصات المبيعات والطلبات والمرتجعات الواردة من الخادم |
| سجل العمليات | عرض أحداث الإدارة المسجلة من الخادم |

كل قسم يدعم حالة التحميل والفشل وإعادة المحاولة والفراغ والبحث. الشاشات تتكيف مع الهاتف والأجهزة اللوحية والشاشات الكبيرة. مؤشرات الملخص تعرض شرطة حتى تحميل البيانات؛ عدد السجلات المحملة ليس إجمالياً محاسبياً. قائمة الصور حالياً من الصور المحلية المضمنة؛ رفع وسائط جديدة وربط مخزن الملفات جزء من التكامل اللاحق.

## حدود الصلاحية

- حذف مدخل «معاينة الإدارة» القديم وحماية مساري `admin` و`admin-list`، بما يشمل الروابط المباشرة.
- لا تقرأ اللوحة دور المستخدم من `localStorage` أو نموذج الدخول أو معلمات الرابط أو حساب العميل التجريبي.
- لا تقبل إلا `authenticated: true` ومستخدم غير `Guest` ودور مطابق تماماً لـ`System Manager` من طبقة النقل المعتمدة في البناء.
- سياق الإدارة مؤقت في الذاكرة فقط؛ يمسح عند إغلاق جلسة الإدارة أو وضع التطبيق في الخلفية أو انتهاء مهلة 60 ثانية أو رد الخادم 401/403. تُغلق النماذج المفتوحة وتختفي السجلات.
- يمنع إرسال حفظين متزامنين. لا تظهر رسالة نجاح قبل تأكيد الخادم. تعارض النسخ 409 يتطلب تحديث السجل ولا يكتب فوقه.
- تستبعد الحقول المقروءة فقط من الحفظ، وتستخدم نسخة السجل المحملة، وليس قيمة نسخة يمكن تغييرها في النموذج.
- حماية واجهة العميل ليست بديلاً عن صلاحيات الخادم. **كل عملية API يجب أن تتحقق من الجلسة والدور وصلاحية المستند وسير العمل داخل ERPNext**. هذا هو الحاجز الأمني للبيانات الحقيقية عند الربط.

Frappe يطبق صلاحيات الأدوار والمستندات على هوية المستخدم الموثّق. يجب الحفاظ على هذه الصلاحيات في كل endpoint مخصص. [توثيق المستخدمين والصلاحيات](https://docs.frappe.io/framework/user/en/basics/users-and-permissions)، [توثيق REST API](https://docs.frappe.io/framework/user/en/api/rest).

## عقد الربط الجاهز للتنفيذ لاحقاً

`app/src/main/assets/web/management-api.js` طبقة نقل معطلة عمداً. يُستبدل تنفيذها أثناء التكامل، ولا يفعّلها زر أو قيمة محفوظة على الجهاز.

| العملية | العقد المتوقع |
|---|---|
| `session()` | سياق المستخدم الحالي فقط: authenticated، user، name، roles؛ بعد مصادقة الخادم |
| `list(module)` | مصفوفة سجلات ذات id وversion وحقول القسم؛ لا يحمّل العميل أكثر من 500 سجل في الصفحة الحالية |
| `save(module,id,payload,version)` | إنشاء/تعديل ضمن حقول مسموحة؛ وعد لا ينجح إلا بعد اعتماد الخادم |
| `archive(module,id,version)` | أرشفة مع تحقق العلاقات وصلاحية الحذف/التعديل؛ دون حذف عشوائي |

تُطبّع أخطاء HTTP إلى كائن يحمل `status`؛ 401/403 يغلقان الإدارة، و409 تعارض نسخة، و503/انقطاع الاتصال يعرضان إعادة المحاولة. عند تسجيل الدخول الحقيقي يستدعي موفر المصادقة `Management.refresh()`؛ وعند الخروج أو تغيير الحساب يستدعي `Management.revoke()` وينهي جلسة الخادم. لا تُخزّن مفاتيح API أو كلمات مرور أو رموز مسؤول ثابتة في JavaScript أو APK.

أُرفق `integration/erpnext/management_guard.py` قالب حارس خادم مع اختبارات مستقلة. يستخدم `frappe.session.user` و`frappe.get_roles` و`frappe.has_permission` ولا يقبل هوية يرسلها العميل. **لم يُنشر هذا القالب على أي خادم، ولا ينفذ CRUD للأقسام بعد**؛ يجب إدماجه واختباره مع إصدار Frappe الفعلي.

## المطلوب في مرحلة الربط

1. تحديد إصدار وموقع ERPNext وآلية دخول المستخدم والجلسة الآمنة.
2. ربط Item وItem Group وSales Order والعملاء والتوصيل بالمخطط الفعلي؛ تعريف DocTypes اللازمة للمحتوى والولاء والمحفظة والتسويق.
3. تطبيق الحارس وصلاحيات كل DocType/مستند على كل طلب؛ لا تستخدم `ignore_permissions` أو واجهة عامة تقبل أسماء DocTypes وحقول غير مقيدة. استخدم استعلامات تحترم صلاحيات المستخدم.
4. تحقق خادمي من الأسعار والمخزون والخصم والهوية والعلاقات، وقواعد الانتقال بين الحالات. موافقة المحفظة تنفذ بسير عمل مالي ذري، لا بمجرد تغيير نص الحالة.
5. منع تكرار العمليات بمفاتيح idempotency، وضبط تعارض النسخ، وسجل تدقيق خادمي لا يستطيع العميل تزويره.
6. تفعيل اتصالات HTTPS لنطاق محدد وتحديث CSP والأذونات بقدر الحاجة فقط؛ لا تفتح WebView لجميع النطاقات. يبقى فتح روابط التواصل منفصلاً وفي المتصفح الخارجي.
7. إكمال رفع الوسائط والترقيم/التصفح لسجلات كبيرة، والتقارير الفعلية، والجدولة والإرسال مع ضوابط الجمهور والموافقة.
8. اختبارات تكامل على خادم تجريبي لدور عادي ودور مدير، مستخدم معطل، سحب الدور أثناء الجلسة، التعارض والانقطاع والمحاولات المكررة؛ ثم توقيع إنتاجي يملكه صاحب التطبيق.

النسخة الحالية مرحلة واجهات مع اختبارات صلاحيات وعقد ربط، وليست تدقيق أمن إنتاجي أو نظاماً متصلاً بمتجر حقيقي.
